这个项目最初的目标是将osm的不同服务器程序进行整合，降低使用的难度，但之后又配合minecraft服务器的运营增加了很多新东西。这些新东西的程序层面均为dsh完成（本人对这些程序一窍不通）。美术素材还是尽可能本人进行编写，但是因为完全一窍不通，目前均为AI生成的占位符符号（没有实际意义）。

这个项目主要有以下几个组建构成，通过docker可以实现联动启动：
	openstreetmap-website：基于 https://github.com/openstreetmap/openstreetmap-website 修改，网页内包括一个iD编辑器。对这个组件的修改仅限于对其一些配置的修改（如在iD增加项目内的瓦片等）。作为整个项目的前端。端口默认为3000。
	osm-carto4mc：为 osm-carto 的分支，该组件提供了处理GIS数据并渲染为成品瓦片等功能。与原版carto最大的不同是增加了大量针对minecraft场景的样式表，根据其他说明为对象使用新的键值对可以让对象表示在minecraft世界中存在的要素，除了原版中的自然要素外也包括人造设施（大到大型电路、刷怪塔，小到挂机池）和模组相关内容（仅提供标准，需要自行添加样式表）。
	sync：项目的关键原创组件，为website和carto数据的桥梁，使其可以互相同步数据。这个组件是专门为在同一个设备运行website与carto设计的，与openstreetmap.org的运营方式不同。若为大型服务器，有大量的io需求，建议像openstreetmap.org一样让carto4mc在独立的主机运行（可以设置多组），但这在我能维护的范围之外了。
	dyn2xyz：相对独立的gis组件，其目的仅为将dynmap这个模组提供的线上地图网站中的瓦片转换为gis软件可以接受的xyz瓦片。可以修改瓦片地址，可以修改线上地图的原点在现实的地理坐标系的坐标。转换后的瓦片为墨卡托投影，在两极会有比例失真，并且考虑到地球面积远小于mc的世界，因此无法在地图开发十分充分的服务器（如2b2t）和某些在未调整边界大小的前提下制作了边界猪人塔的生电服务器使用。
